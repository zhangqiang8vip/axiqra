## 1. 文档定位

本文档定义 Axiqra 的完整原型和页面体系。

它只回答页面层问题：

1. 当前 Vue 原型已经有哪些页面和交互。
2. 哪些页面必须继承当前原型的布局、配色和结构。
3. 哪些完整产品形态必须在原型中展示，即使 MVP 首版不完整实现。
4. 页面之间如何组织导航、入口、状态和流转。
5. 每类页面需要展示哪些核心对象、状态、动作和风险提示。
6. 哪些页面只负责展示，哪些页面需要在首版具备真实闭环。

本文档不决定 MVP 的研发范围。页面完整展示不等于首版全部开发完成。D04 负责把本文档中的页面能力拆成 MVP、内测、公开阶段、团队企业阶段和后续生态阶段。

## 4. 原型总原则

### 4.1 完整原型先行

Axiqra 当前阶段的原型必须尽量展示完整产品形态。

原因：

1. 原型是理解产品最快的方式。
2. 原型是团队、投资人、开发者和早期用户传播产品的主要材料。
3. 原型可以直接反推页面对象、数据模型、权限边界、状态机和实现优先级。
4. 看不见的能力很难被评审、讨论和优化。
5. 如果原型只做低配 MVP，后续容易以补丁方式增加团队、企业、治理、激励和接入，导致文档和系统都变乱。

因此，D03 采用“完整页面展示”原则。D04 再决定哪些页面首版真实开发，哪些页面只做静态展示或灰态入口。

### 4.2 原型不是首版承诺

完整原型必须把产品未来形态展示出来，但不能把所有展示内容都写成 MVP 已实现。

页面中应明确区分：

| 页面状态 | 含义 | 展示方式 |
|---|---|---|
| 已实现原型 | 当前 Vue 原型已有可交互页面 | 可点击、可筛选、可复制、可演示 |
| 需补齐原型 | 当前资料要求存在但原型还不完整 | D03 标注必须新增 |
| MVP 必须真实闭环 | 首版不能只展示，必须能跑通 | D04 继续拆实现范围 |
| MVP 可灰态展示 | 首版可展示但暂不完整实现 | 页面标注“即将支持”或“试点阶段” |
| 长期探索 | 长期方向，不作为当前承诺 | 页面可在路线、说明或附属区域低优先级展示 |

### 4.3 页面必须服务双主线

页面体系必须同时服务两条主线：

1. AI 调用主线：接入、检索、读取 Solution、生成 Engineering Trace Package、用户确认、回传 Case Package、反馈 worked / failed / partial / not_applicable。
2. 人类学习主线：搜索、阅读 Public Case、理解排查过程、查看失败路径、进入学习模式、收藏和反馈。

不能只做 AI 接口页面，也不能只做案例阅读页面。

### 4.4 团队和企业能力必须可见

团队空间、企业空间、权限隔离、数据隔离、审计、导出、私有化、内部 AI 调用、Owner Review、学习复盘等能力必须进入完整原型。

MVP 可以分阶段实现，但页面不能缺席。缺席会导致后续无法清楚评估数据模型、权限模型和商业试点路径。

### 4.5 对话式自动接入必须成为主体验

接入页不能只展示命令行或 MCP 配置。完整原型必须把“复制给智能体，让智能体自动读取、安装、授权、配置、检测”的流程做成首要入口。

Skill Pack 只是接入包的一种可能形态。页面应使用更大的口径：对话式自动接入、接入包、MCP、CLI、API、SDK、插件和降级路径。

### 4.6 首页必须先是开放互联网级 SaaS 产品

完整原型不能继续把首页做成企业内部系统、私有知识库、管理后台或安全合规平台。

首页和公开传播页面的主叙事必须是：

```text
面向全球开发者、AI 工具用户、开源维护者、社区、小团队、企业和大集团的 AI Agent 工程记忆基础设施。
```

首页前几屏必须优先回答：

1. Axiqra 是什么。
2. AI Agent 为什么需要它。
3. 个人开发者怎么用。
4. 小团队怎么共用。
5. Solution 如何被 AI Agent 调用、验证和反馈。

企业权限、空间管理、组织治理、审计、SSO / SCIM 和大集团治理能力必须存在，但应放在成长路径中的高级阶段或后半部分，不能成为首页默认主角。

首页信息架构必须遵守：

```text
是什么 -> 为什么需要 -> 怎么工作 -> 谁能用 -> 为什么可信 -> 怎么接入 -> 开始使用
```

### 4.7 个人到大集团的成长路径必须清楚

首页必须明确展示以下成长路径：

```text
个人开发者 -> 小团队 / 团队 -> 企业 -> 大集团
```

每一层都要说明适合谁、解决什么和能力重点：

| 层级 | 页面表达重点 |
|---|---|
| 个人开发者 | 把自己的踩坑经验变成 AI 可复用的个人工程记忆 |
| 小团队 / 团队 | 让项目经验被团队成员和 AI Agent 共同复用 |
| 企业 | 沉淀可信、可审查、可治理的工程 Solution |
| 大集团 | 构建跨组织、跨项目、跨 Agent 的工程记忆网络 |

企业能力是重要能力，但不是首页唯一主线。个人和小团队不能被写成企业能力的弱化版。

### 4.8 禁止安全产品化和合规控制台化

Axiqra 可以表达可信、授权、脱敏、权限、风险、验证、审核和内容质量治理，但不能使用安全产品、防火墙或合规控制台的叙事。

原型文案禁止使用以下方向：

```text
安全隔离区
安全防线
物理防穿透
安全防空洞
防火墙
安全管控中心
合规驾驶舱
威胁拦截
入侵防护
```

推荐替代表达：

| 不推荐 | 推荐 |
|---|---|
| 安全隔离区 | 私有内容区 / 企业私有内容 / 受限可见内容 |
| 安全防线 | 授权边界 / 可见范围 / 使用范围 |
| 物理防穿透 | 权限边界清晰 / 不跨空间泄露 |
| 安全防空洞 | 待复核风险 / 未授权风险 / 脱敏缺口 |
| 防火墙 | 治理规则 / 访问控制 / 授权策略 |
| 安全管控中心 | 治理队列 / 审核中心 / 权限与授权设置 |
| 合规驾驶舱 | 企业审计 / 使用记录 / 授权概览 |

“内容污染”相关机制在页面上应优先表达为内容质量治理、暂停推荐、复核、版本废弃或维护者审核，避免让用户误以为 Axiqra 是安全管理系统。

## 7. 全局导航与信息架构

### 7.1 顶部导航

顶部主导航采用“扁平极客行（Flex Row）”架构。为了确立全球互联网级 SaaS 平台的气质，必须在一级主导航中常驻平铺 8 个主要功能路由，杜绝将大量主链接折叠藏匿；对于次要的管理和系统设置，折叠收纳在“更多 ▾”下拉菜单内。

> [!IMPORTANT]
> **视觉与交互核心 CSS 重构指标：**
> 1. **`1240px` 顶级 CSS Flex 响应式折合机制**：
>    * 一级导航项中，前 4 项（首页、检索工作台、Solution、Public Case）为绝对常驻。
>    * 后 4 项（接入、社区、团队、企业）打上 `.nav-item-responsive` 标识。
>    * 同时，在“更多 ▾”下拉菜单的 `.dropdown-content` 中反向映射 4 个 `.drop-item-responsive` 链接。
>    * **纯 CSS 响应式规则**：当视口宽度低于 `1240px` 时，通过 `@media (max-width: 1240px)` 自动 `display: none` 隐藏导航栏中的响应式项，并 `display: block` 激活下拉菜单中的映射项。实现纯 CSS 零 JS 开销的导航栏完美折叠，防止路由栏拉伸换行或变形。
> 2. **下拉框零间隙 Hover 桥接原则 (Dropdown translateY Bridge)**：
>    * 下拉菜单触发器（`.dropdown-btn`）和悬浮内容（`.dropdown-content`）在 DOM 绝对定位时，通过 `top: 100%` 进行底部无缝对齐，配合适当的 `translateY` 产生平滑视觉间隙，但物理盒模型必须保持重叠接触。
>    * **接触死角消除**：严禁在触发器和悬浮窗之间留有透明的物理物理“空白空气区”。一旦留空，当用户鼠标从按钮向下滑入菜单时，会触发 `mouseleave` 导致菜单瞬时关闭。必须在气泡层上使用微量偏移或隐式伪元素（`:before` padding 扩充）进行桥接。

## 8. 核心页面说明

### 8.1 首页

首页是 Axiqra 的第一屏产品体验，不应做成单纯宣传页。

首页必须同时让用户看到：

1. Axiqra 是工程方案记忆层。
2. 可以直接搜索工程记忆。
3. 有可被 AI 调用的 Solution。
4. 有人类可读的 Public Case。
5. 有产品演示台。
6. 有接入 AI 工具的入口。
7. 有团队 / 企业价值的可见信号。

当前原型已具备：

| 区块 | 当前作用 | 后续处理 |
|---|---|---|
| 主搜索区 | 输入报错或关键词进入搜索 | 保留 |
| 左侧 Solution 滚动卡片 | 展示已验证方案 | 状态升级为 L0-L5 + R0-R4 + 样本量 |
| 右侧 Public Case 滚动卡片 | 展示公开案例 | 增加学习模式标识 |
| 产品演示卡片 | 引导到 `/pilot` | 保留 |
| 指标卡片 | 展示 Case、工具、试点等信号 | 数字必须标注为样例或真实统计 |
| 接入 CTA | 引导到 `/connect` | 改成对话式自动接入 |
| 视觉风格切换 | A / B 风格 | 保留 |

需要新增或加强：

| 需补齐内容 | 原因 |
|---|---|
| 团队 / 企业入口信号 | 用户已确认必须展示，不应只藏在个人空间 |
| 对话式自动接入主 CTA | 快速传播和真实接入第一入口 |
| 公开内容授权和脱敏提示 | 防止用户误以为 Project Case 自动公开 |
| L0-L5 可信展示说明 | 防止把高成功率误写成绝对可信 |
| 低样本提示 | 避免 1 次成功显示为 100% |

### 8.2 搜索页

搜索页是 AI 调用和人类检索的共同入口。

当前原型已有：

1. 搜索框。
2. Solution / Public Case 混合结果。
3. 全部、解决方案、公开案例 Tab。
4. 技术栈筛选。
5. 验证等级筛选。
6. 排序。
7. 空结果 Candidate Seed。
8. 覆盖范围链接。
9. 移动端筛选面板。

必须补齐：

| 内容 | 要求 |
|---|---|
| 验证等级 | 从 L1-L3 扩展为 L0-L5 |
| 风险等级 | 展示 R0-R4，且与验证等级分开 |
| 样本量 | 展示适用调用次数、worked / partial / failed / not_applicable |
| 低样本提示 | 少于 5 次适用调用不显示成功率百分比 |
| 上下文匹配 | 展示技术栈、版本、部署环境、产品阶段是否匹配 |
| 权限提示 | 搜索结果必须明确来自公共空间、个人空间、团队空间或企业空间 |
| 空结果 | 不返回不相关方案，只能提交 Candidate Seed 或查看覆盖范围 |
| 无权限结果 | 可提示存在但不可见，不泄露企业内容 |

搜索页不得：

1. 用泛化结果填充空结果。
2. 只按成功率排序。
3. 忽略权限后全局召回。
4. 把 Public Case 当成默认推荐方案。

### 8.3 覆盖范围页

覆盖范围页用于告诉用户当前哪些技术栈、问题类型和场景有可信记忆，哪些还没有。

当前原型已有覆盖组、无命中处理、暂不推荐范围。

必须保留：

1. 已覆盖技术栈。
2. 未覆盖或仅 Candidate Seed 的范围。
3. 无命中时不乱推荐的说明。
4. Coverage 不足时进入 Candidate Seed / Needs Review。
5. Related Reference 的边界说明。

需要补齐：

1. 覆盖范围按个人、团队、企业、公共空间分层展示。
2. 覆盖范围按 case_type 展示。
3. 覆盖范围按 L0-L5 展示。
4. 覆盖范围按最近验证时间展示。
5. 覆盖范围按风险等级展示。

### 8.4 Public Case 列表页

Public Case 列表页服务人类学习和公开传播。

当前原型已有：

1. 公开案例证据层说明。
2. 类型筛选。
3. 验证等级筛选。
4. 本周精选。
5. 案例列表。
6. 无结果 Candidate Seed。

必须强化：

| 页面元素 | 要求 |
|---|---|
| 证据层说明 | Public Case 是证据层，不直接等于最终推荐方案 |
| 学习入口 | 每个 Case 卡片应提示可进入学习模式 |
| 脱敏状态 | 标注公开案例已经授权、脱敏、审核 |
| 归并关系 | 展示关联 Solution、Problem Cluster 或 root_cause 分支 |
| 贡献来源 | 展示来源类型和贡献者，不暴露敏感信息 |
| 反馈入口 | 支持标记有用、误导、不适用、需要复审 |

Public Case 列表不应：

1. 把未脱敏 Project Case 混入公开列表。
2. 把 Public Case 直接标成 Canonical Solution。
3. 展示企业私有信息。

### 8.5 Public Case 详情页

Public Case 详情页是人类学习主线核心页面。

当前原型已有结构：

1. 真实工程证据层提示。
2. 案发现场。
3. 命令行排查证据。
4. 根因与 AI 误判。
5. 最终修复与验证。
6. 假设验证与失败路径。
7. 新手复盘与学习问题。
8. 左侧目录。
9. 右侧作者、指标、技术栈、授权与风险说明。

必须保留并增强：

| 区块 | 增强要求 |
|---|---|
| 案发现场 | 展示环境、版本、错误签名、任务类型、风险等级 |
| 排查证据 | 展示命令、日志、截图、CI、PR / Issue 等证据类型 |
| AI 误判 | 展示常见错误建议和为什么不适用 |
| 失败路径 | 不作为噪音，必须可见 |
| 学习层 | 面向新手解释概念、错因、自检问题和延伸学习 |
| 关联 Solution | 明确它是证据来源还是推荐方案 |
| 脱敏说明 | 说明公开内容不含私有路径、Token、内部域名和客户数据 |
| 反馈 | 支持 worked / failed / partial / not_applicable 或学习反馈入口 |

### 8.6 Solution 列表页

Solution 列表页服务 AI 调用和高级开发者快速筛选。

当前原型已有：

1. 搜索。
2. 任务类型筛选。
3. 推荐方案封面。
4. Solution 卡片列表。
5. Candidate Seed 提交。
6. 侧边模型 / 工具效能榜。
7. 脱敏防护说明。

必须补齐：

| 内容 | 要求 |
|---|---|
| 状态全集 | Draft、Candidate、Needs Review、Verified、Stable、Canonical、Deprecated、Rejected、Archived、Quarantined |
| 验证等级 | L0-L5 |
| 风险等级 | R0-R4 |
| 样本量展示 | 适用调用次数、worked、partial、failed、not_applicable |
| 维护状态 | Maintained、Needs Review、Version Review、Quarantined 等 |
| 适用边界 | 卡片上必须出现适用 / 不适用摘要 |
| 权限来源 | public、team、enterprise、official seed、dogfooding 等 |
| 排序解释 | 为什么被推荐，而不是只显示高分 |

Solution 列表不得只展示成功率。成功率必须和样本量、验证等级、风险等级、上下文匹配一起出现。

### 8.7 Solution 详情页

Solution 详情页是 AI 调用主线核心页面。

当前原型已有：

1. 执行模式。
2. 学习解释模式。
3. AI 指令复制。
4. 左侧目录。
5. 右侧指标。
6. 技术栈。
7. 发布声明。

必须强化：

| 区块 | 要求 |
|---|---|
| 顶部摘要 | 标题、状态、L 等级、R 等级、维护状态、最近验证时间 |
| 执行模式 | 给 AI 和高级开发者读取，突出步骤、前置条件、验证和回滚 |
| 学习模式 | 给人类开发者读取，解释为什么这样做、为什么常见方案不适用 |
| 适用边界 | 独立展示适用场景、不适用场景、前置条件 |
| 风险与回滚 | 中高风险必须显示回滚或人工确认提示 |
| 验证证据 | 展示证据类型、样本量、独立工程上下文数量 |
| 调用反馈 | 展示 worked / partial / failed / not_applicable |
| 关联 Case | 展示归并的 Public Case / Project Case 证据来源 |
| 生命周期 | 展示升级、分叉、废弃、隔离入口或状态说明 |

高风险 Solution 即使 L5，也必须在页面上提示不能自动执行。

### 8.8 对话式自动接入页

接入页是当前需要重点重构的页面。

当前原型已有：

1. MCP 配置。
2. CLI 初始化。
3. Agent Rule Pack。
4. OpenAPI 预览。
5. SDK 示例。
6. 导入导出。
7. MCP 工具说明。
8. doctor 自检。
9. 失败预设和修复命令。

必须调整为以下优先级：

| 优先级 | 页面模块 | 页面要求 |
|---:|---|---|
| 1 | 对话式自动接入 | 用户复制一段接入指令给 AI 工具，AI 自动读取接入说明并完成安装、授权、配置、检测 |
| 2 | 接入包 / Skill Pack | 展示可安装接入包、包含文件、安装清单、适配工具、版本和更新方式 |
| 3 | 授权与绑定 | 展示授权码回填、绑定状态、工作区选择、项目选择 |
| 4 | 接入状态检测 | doctor 检查 CLI、MCP、Rule Pack、权限、搜索、提交、反馈 |
| 5 | 工具兼容矩阵 | Cursor、Claude Code、Codex、OpenClaw、Copilot、Gemini CLI、自研 Agent |
| 6 | MCP / CLI / API / SDK | 作为底层能力和降级路径展示 |
| 7 | 失败诊断 | 未安装、未登录、代理错误、权限不足、配置冲突、网络不可达 |
| 8 | 回传规则 | Engineering Trace Package 生成、用户确认、Case Package 提交、禁止自动发布、禁止自动 Verified |
| 9 | 工程轨迹确认 | 展示正向路径、反向路径、决策路径、证据路径、回滚路径和演化路径 |

接入页必须支持的核心状态：

| 状态 | 页面表现 |
|---|---|
| Not Connected | 尚未接入，展示复制给智能体入口 |
| Installing | 智能体正在安装接入包或配置 MCP / CLI |
| Awaiting Auth | 等待用户授权或回填授权码 |
| Verifying | 正在执行 doctor 检测 |
| Connected | 接入完成，可调用 search_solution |
| Degraded | MCP 不可用，降级到 CLI / API |
| Failed | 接入失败，展示诊断日志和修复命令 |
| Needs Update | 接入包版本过旧，需要更新 |

接入页不能：

1. 只展示命令行。
2. 只展示 MCP JSON。
3. 把 Skill Pack 写成唯一形态。
4. 只做静态宣传，不展示真实安装和检测状态。

### 8.10 Project Case 详情页

Project Case 是私有或受限空间内的工程记录。

当前原型已有：

1. 原始日志。
2. 私有可见提示。
3. 脱敏发布 CTA。
4. LLM 脱敏发布弹窗。
5. 原始日志与脱敏预览对比。
6. 发布前勾选确认。
7. 提交审核后的状态。

必须补齐：

| 能力 | 页面要求 |
|---|---|
| 可见性 | 明确 private / team / enterprise / public |
| 敏感等级 | 标注敏感字段、私有附件、客户数据、内部路径 |
| 发布路径 | Project Case -> 脱敏预览 -> Owner Review -> Candidate Public Case |
| 审核结果 | Approved、Rejected、Needs Review、Quarantined |
| 回传来源 | AI 工具、CLI、MCP、导入、手工创建 |
| 工程轨迹 | 正向路径、反向路径、决策路径、证据路径、回滚路径、演化路径 |
| 原始证据 | 日志、命令、截图、CI、PR、Issue、监控 |
| 删除与导出 | 可导出、可删除、可撤回授权 |

Project Case 页面不得允许一键自动公开。

当前原型的 ProfileView 已经包含大量团队大盘元素，可以作为团队空间基础。

团队空间应包含：

| 页面模块 | 展示内容 |

| 团队 Solution | Team Solution、内部 Canonical、适用边界 |
| Owner Review | 待复审队列、过期方案、Owner 转移、风险复核 |
| Learning Mode | 新人学习次数、收藏、学习后 Draft、团队学习路径 |
| 调用统计 | 工具、Agent、模型、调用次数、worked / failed / partial |
| 覆盖热力图 | case_type 覆盖、技术栈覆盖、无命中类型 |

### 8.12 企业空间页

企业空间是完整产品形态中必须存在的页面域。

企业空间应展示：

| 页面模块 | 展示内容 |
|---|---|
| 企业总览 | 租户、项目数量、团队数量、内部 Case、内部 Solution、接入工具 |
| 租户与空间 | 企业空间、团队空间、项目空间、公共贡献隔离 |
| 成员与权限 | 角色、权限矩阵、管理员、审计员、维护者 |
| 企业 AI 接入 | 企业自研 Agent、内部 MCP、私有 API、模型网关 |
| 数据隔离 | 默认不公开、不训练、不进入公共收益池 |
| 审计日志 | 登录、授权、导出、删除、审核、接入、调用 |
| 数据导出 | JSONL、Markdown ZIP、CSV 统计、审计导出 |
| 删除与撤回 | 删除证明、授权撤销、索引删除传播状态 |
| 私有化路线 | SaaS、专属租户、私有部署、混合部署 |
| SSO / SCIM | 必须展示企业身份接入能力，可灰态但要说明能力边界 |
| 企业试点 | 试点 Gate、ROI、覆盖率、调用价值、风险项 |

企业空间页面必须反复提示：企业数据默认不公开、不训练、不进入公共收益池，除非明确授权。

### 8.13 内容治理后台

内容治理后台不一定首版开放给普通用户，但完整原型必须展示其存在。

治理后台应包含：

| 页面模块 | 展示内容 |
|---|---|
| 审核队列 | Draft、Candidate、Needs Review、Public Case 发布申请 |
| 脱敏审核 | 敏感字段、替换预览、人工确认、打回 |
| 可信来源 | 官方种子、认证贡献者、开源项目、企业授权、Dogfooding |
| 污染隔离 | 低质、抄袭、刷量、恶意内容、危险内容 |
| 风险分层审核 | 极低风险自动通过 / 拒绝 / 要求补充，低风险抽检，中高风险人工或认证审核 |
| 风险复核 | R3 / R4、高风险方案、生产数据、权限、支付 |
| 举报申诉 | 举报、申诉、处理状态、仲裁入口 |
| Quarantined | 隔离内容，仅治理角色可见 |
| 审核日志 | 审核人、时间、理由、证据、结果 |

治理后台边界进入 D14 / D16，D03 只定义页面必须存在和展示什么。

### 8.14 贡献者与激励页

贡献者与激励页必须在完整原型中出现，因为旧资料和用户确认都包含贡献、积分、权益、收益池方向。

页面应展示：

| 页面模块 | 展示内容 |
|---|---|
| 贡献总览 | Case、Solution、反馈、审核、维护、学习贡献 |
| 贡献账本 | 每次贡献来源、对象、状态、质量、授权、反作弊状态 |
| 积分 | 学习积分、贡献积分、维护积分 |
| 权益 | API 权益、Pro 抵扣、认证标识、优先试点资格 |
| 能力档案 / 认证凭证 | 认证领域、等级、有效期、复核周期、撤销状态、公开验证入口 |
| 收益池资格 | 只展示资格、规则和未来分配原则，不写固定比例 |
| 归因链路 | Solution 调用、worked 反馈、企业采用、评测集入选 |
| 反作弊提示 | 抄袭、刷 worked、重复提交、未授权导入不计资格 |
| 待确认说明 | 资金使用和固定比例后续商业化阶段确认 |

该页面不能承诺现金收益比例，也不能暗示所有贡献都会获得现金收益。

### 8.15 演示台

产品演示台是传播和理解页面，当前 `/pilot` 已经很好地承接了“用一个 Redis 报错跑完整流程”的方式。

必须保留的演示步骤：

1. 用户贴问题或报错。
2. AI 先查工程记忆。
3. 命中 Solution 或相关 Public Case。
4. 展示常见错误方向和为什么不适用。
5. 展示可执行方案、验证步骤和风险提示。
6. 任务结束后生成 Engineering Trace Package。
7. 用户确认工程轨迹后才能提交 Candidate 或 Project Case。
8. 不自动发布，不自动 Verified。
9. worked / failed / partial / not_applicable 只更新反馈和复审信号。

演示台可以用 mock 数据，但必须避免把 mock 统计写成真实生产能力。

### 8.16 关于与传播页

关于页和传播页用于解释价值、试点、冷启动和外部传播。

当前 `/about` 已有价值测算、通用接入提示词、愿景表达等内容。

D03 只要求：

1. 保留对外传播页面。
2. 页面不替代 D02 的产品定位。
3. 页面不替代 D17 的商业验证。
4. 页面中的 ROI、节省成本、团队效率数字必须标注为测算、样例或试点数据。
5. 页面应引导到接入、演示、公开案例和试点申请。

## 9. 视觉设计继承规范

### 9.1 视觉方向

用户已确认现有原型的整体布局、结构和配色方向可以优先借鉴。

后续页面应继承当前 Vue 原型的基调：

1. 工作台式，而不是纯营销页。
2. 信息密度适中，适合工程师扫描。
3. 浅色暖底为默认，深色风格作为展示开关。
4. 蓝色作为主强调色。
5. 绿色表示成功、有效、通过。
6. 琥珀色表示候选、低样本、待复审、风险提示。
7. 红色表示失败、危险、隔离、禁止。
8. 代码和终端使用深色块。
9. 卡片用于具体对象，不用把整个页面层层套卡片。
10. 页面应保留工程感、证据感和可信感。

### 9.2 现有颜色令牌

后续原型可继续沿用以下视觉变量方向。

| 令牌 | 当前含义 | 页面使用 |
|---|---|---|
| `--bg` | 页面背景 | 全局背景 |
| `--surface` | 主表面 | 面板、列表、详情块 |
| `--surface-2` | 次级表面 | 侧栏、信息块、卡片背景 |
| `--surface-3` | 第三级表面 | 输入、筛选、代码外层 |
| `--border` | 主边框 | 面板和分割 |
| `--text` | 主文字 | 标题、重要信息 |
| `--text-2` | 次级文字 | 摘要、说明 |
| `--text-3` | 弱文字 | 元数据、提示 |
| `--accent` | 主强调蓝 | 主按钮、链接、选中态 |
| `--green` | 成功 | worked、通过、Verified |
| `--amber` | 候选 / 风险 | Candidate、低样本、Needs Review |
| `--red` | 危险 | failed、Quarantined、拒绝 |

### 9.3 状态色规则

| 状态类型 | 颜色倾向 | 页面用法 |
|---|---|---|
| Verified、worked、pass、connected | 绿色 | 成功、通过、已接入 |
| Candidate、Needs Review、partial、low sample | 琥珀色 | 候选、待复审、低样本 |
| failed、Rejected、Quarantined、R4 | 红色 | 失败、隔离、禁止自动执行 |
| Draft、Archived、not_applicable | 灰色或蓝灰 | 草稿、归档、不适用 |
| Canonical、Stable、L4 / L5 | 蓝色 + 绿色组合 | 高可信但不绝对正确 |

状态色必须和文字同时出现，不能只靠颜色区分。

### 9.4 布局规则

| 场景 | 推荐布局 |
|---|---|
| 首页 | 中央搜索 + 两侧方案 / 案例 + 演示和接入 CTA |
| 列表页 | 搜索 / 筛选在上，列表为主，侧栏展示说明或榜单 |
| 详情页 | 左目录、中正文、右指标 |
| 工作台 | 左侧空间导航 + 右侧主内容 |
| 接入页 | 顶部对话式接入 + 下方协议 / 诊断 / 兼容矩阵 |
| 企业后台 | 左侧空间 / 权限导航 + 主内容表格和审计 |
| 治理后台 | 队列 + 详情抽屉 / 审核日志 |
| 移动端 | 单列、筛选折叠、侧栏隐藏或抽屉化 |

页面应避免大段说明文字占满首屏。首屏要有可操作入口。

## 10. 核心交互规则

### 10.1 搜索交互

搜索输入后：

1. 先显示匹配数量和查询词。
2. 支持全部、Solution、Public Case、Project Case 分层。
3. 支持按技术栈、验证等级、风险等级、空间、任务类型筛选。
4. 支持按当前项目、小组 / Squad、团队、企业 / 组织、已授权公共内容、普通公共内容的空间优先级排序。
5. 支持按上下文匹配、最近验证、维护状态排序。
6. 空结果不返回不相关内容。
7. 空结果允许提交 Candidate Seed。
8. 无权限结果不泄露具体内容。

### 10.2 Candidate Seed 交互

Candidate Seed 出现位置：

1. 搜索空结果。
2. Public Case 列表空结果。
3. Solution 列表空结果。
4. 覆盖范围不足页。
5. 接入后 AI 任务后回传。

规则：

1. 默认进入 Candidate Seed 草稿或候选池。
2. 支持大众创建，但必须展示基础质量门槛。
3. 基础质量门槛至少包括真实上下文、用户确认、验证证据和风险说明。
4. 未达到门槛时保持低权重草稿或要求补充。
5. 达到门槛后可进入 Candidate Pool，由大众继续补充，或由维护者、认证开发者、认证审核者认领协作。
6. 不能自动公开。
7. 不能自动 Verified。
8. 需要按风险等级进入 AI 初审、抽检复核、人工审核或认证审核。

### 10.3 详情页阅读模式

Solution 详情页必须保留双模式：

| 模式 | 面向对象 | 重点 |
|---|---|---|
| 快速执行模式 | AI 工具、高级工程师 | 步骤、前置条件、验证、回滚、风险 |
| 学习解释模式 | 新人、学习型用户、转岗开发者 | 为什么、误区、根因、概念、自检问题 |

Public Case 详情页也应体现学习层，但不一定用完全相同的开关。

### 10.4 对话式自动接入交互

完整原型必须展示以下交互链：

1. 用户选择工具。
2. 用户复制一段接入指令给智能体。
3. 智能体读取接入包或接入描述。
4. 页面显示等待授权。
5. 用户回填授权码或确认绑定。
6. 页面显示安装产物。
7. 页面执行 doctor 检测。
8. 成功后显示可调用能力。
9. 失败时显示诊断日志和修复建议。

### 10.5 脱敏发布交互

Project Case 发布为 Public Case 的页面链路：

1. 用户打开 Project Case。
2. 页面提示原始内容仅个人 / 团队 / 企业可见。
3. 用户点击脱敏发布。
4. 系统扫描敏感信息。
5. 页面展示原始内容和脱敏预览对比。
6. 用户勾选确认不包含敏感信息。
7. 提交审核。
8. 进入 Needs Review。
9. 审核通过后成为 Public Case 或 Candidate Public Case。

### 10.6 反馈交互

所有 AI 调用和人类使用反馈必须保留细分结果：

| 反馈 | 页面含义 |
|---|---|
| worked | 当前上下文有效 |
| partial | 部分有效，需要拆分步骤 |
| failed | 失败，需要复审、降级或更新边界 |
| not_applicable | 当前上下文不适用，应更新适用边界 |
| needs_review | 用户认为需要人工复审 |

not_applicable 不能算失败，但必须影响边界和匹配。

## 19. 视觉与硬核交互技术规范 (Visual & Sandbox Spec)

为了确保后续开发和正式工程前端完全对齐当前原型沉淀的 **“互联网级 SaaS 气质”** 与 **“物理级交互质感”**，页面与样式编码必须遵循以下硬性指标：

### 19.1 视觉要素与主题设计变量 (Visual Design Tokens)
*   **字体排版 (Typography)**：全站一级 H1/H2 标题、卡片头部及 Workspace 标签必须采用极客质感的 `Outfit` 或 `Inter` 无衬线现代字体；对于配置代码、接入指令、错误日志、自检诊断终端等流式输出，强制使用 `Courier New`、`Monaco` 或标准的等宽字体族（`font-family: monospace`）。
*   **磨砂玻璃特效 (Glassmorphism)**：全站所有弹出层（Popover）、对话框（Modal）、全局检索框（Ctrl+K）、上下文下拉选择器和用户头像菜单，必须设置毛玻璃底色与柔和边框，并在 Hover 时伴随微小的位移与平滑投影过渡：
    ```css
    background: rgba(255, 255, 255, 0.85);
    backdrop-filter: blur(10px);
    border: 1px solid rgba(0, 0, 0, 0.08);
    transition: all 0.25s cubic-bezier(0.4, 0, 0.2, 1);
    ```
*   **尺寸稳定性 (Card Sizing)**：解决方案卡片（`SolutionCard`）与案例卡片（`CaseCard`）在 hover 时仅允许发生微量向上悬浮（配合阴影加深），**绝对禁止因为 hover 改变卡片的 Padding、Border 粗细、Margin 或 Flex-Basis 等物理尺寸参数**，彻底防御在滚动与加载时的列表布局抖动。

### 19.2 诊断终端与配置网格防挤压规约 (Terminal Grid Layout Rules)
*   当 Prompt 配置展示框（左侧）与本地 Doctor 自检控制台（右侧）在 Grid 容器中并行渲染时，**必须防止长文本撑爆右侧控制台**。
*   **CSS 防挤压规约**：左侧 pre/code 代码容器必须显式声明宽度限制，并且外层网格列必须使用 `min-width: 0`：
    ```css
    .config-content {
      white-space: pre-wrap;
      word-break: break-all;
      overflow-wrap: break-word;
    }
    .connect-grid {
      display: grid;
      grid-template-columns: repeat(2, minmax(0, 1fr));
      gap: 24px;
    }
    ```
    此配置强行阻断了由于 pre/code 元素默认 `min-width: min-content` 导致的父容器强制挤压变形，确保在 $1024px \sim 1366px$ 屏幕上左右两栏维持完美的 `50%` 对等平分。

### 19.3 动态交互沙箱物理计算引擎规则 (Interactive Sandbox Calculations)
*   **L0-L5 鲜活度进化模拟**：
    *   在 worked/failed 反馈沙箱中，当总调用数 `total < 5` 时，前端界面必须隐藏成功率百分比，显示为 `数据积累中... (N/A)`（规避低样本偏差）；
    *   当连续模拟 `👍 worked` 导致 `total >= 5` 时，释放并实时渲染百分比成功率：
        $$\text{success rate} = \left( \frac{\text{worked} + \text{partial} \times 0.5}{\text{total}} \right) \times 100\%$$
        成功率不低于 `80%` 且 `total >= 5` 时，实时在 L0-L5 进化线上推进节点，并伴随过渡色（从灰色转为高级绿色）。
*   **SaaS 研发工时效能成本计算器**：
    *   滑动“每月生产级故障数 (Monthly Incidents)”滑块，数据必须在 UI 界面发生毫秒级响应，应用如下公式完成算力转换，消灭硬编码：
        $$\text{Saved Hours} = \text{Monthly Incidents} \times 2.4 \text{ hrs (单次借阅记忆减免工时)}$$
        $$\text{Saved Cost (\$)} = \text{Saved Hours} \times 50 \text{ USD (研发骨干时薪折算)}$$
        结果采用高级绿色字重显示，并辅以 FTE 劳动力解放折算，直观展示商业试点价值。
*   **Live Redactor 脱敏沙箱**：
    *   支持用户输入真实的敏感配置，点击自检后， mock 脱敏正则表达式引擎必须对输入文字完成正则分析，并在 UI 上输出脱敏 Diff 对比界面，标出被替换出的 `DB_PASS=Secret***` 与内网 IP 片段。
