# 测试执行记录模板

## 1. 记录说明
本模板用于归档单次测试执行结果，适用于定向测试、模块测试、回归测试与发布前验证记录。

使用原则：
- 文件名使用英文；
- 文件内容使用中文；
- 记录正式结论，不粘贴大段原始日志；
- 原始产物仅作为辅助追溯来源。

## 2. 模板正文

```text
# <测试场景名称> 测试记录

## 1. 记录说明
本记录用于归档 `<测试场景名称>` 的一次正式测试执行结果。

## 2. 测试对象
- 模块：`<module-name>`
- 测试类/测试场景：`<test-class-or-scenario>`
- 相关文件：`<related-file-path>`

## 3. 测试目标
- <目标 1>
- <目标 2>
- <目标 3>

## 4. 执行信息
- 执行时间：`YYYY-MM-DD HH:mm（时区）`
- 执行目录：`<working-directory>`

执行命令：

<command>

## 5. 测试结果
- Tests run：`<n>`
- Failures：`<n>`
- Errors：`<n>`
- Skipped：`<n>`
- Time elapsed：`<time>`
- 最终结论：`PASSED` / `FAILED`

## 6. 归档摘要
<用一段话总结本次验证结论、覆盖范围与风险判断>

## 7. 原始结果来源
- `<temporary-result-path-1>`
- `<temporary-result-path-2>`

## 8. 后续动作
- <是否需要补充测试>
- <是否需要追加修复>
- <是否需要更新清单或模板>
```

## 3. 使用建议
- 定向测试结果归档到 `reports/`；
- 同一类场景若长期重复执行，建议按日期或场景拆分独立文件；
- 若测试失败，应在“后续动作”中明确补救措施。
