## 1. 文档定位

本文档不描述任何已存在页面稿，也不要求继承任何历史页面、历史路由、历史配色或历史交互。

当前项目按从 0 开始处理：先完成产品文档、流程、对象、权限、技术方案和 Excel 功能拆解；等文档和 Excel 齐全后，再基于功能点重新设计原型。

本文档只定义未来原型设计时必须遵守的页面原则、入口策略、信息架构和验收边界。

## 2. 从 0 开始的设计原则

| 原则 | 说明 |
|---|---|
| 文档先于原型 | 先确认产品范围、对象、流程、权限、接口和验收，再设计原型 |
| Excel 先于页面细节 | 功能点、页面点、对象字段、API 和验收标准齐全后，再画页面 |
| 互联网入口优先 | 公开入口服务个人开发者、AI 工具用户、开源维护者和大众贡献者 |
| 累加式权限渲染 | 团队、企业、小组、审核、维护等入口由登录态、空间成员关系、授权范围和治理职责累加决定 |
| 不默认企业后台化 | 未登录或普通用户不应先看到企业权限、组织治理、SSO、审计后台 |
| 不继承历史页面 | 历史页面只能作为背景参考，不作为设计约束 |
| 先闭环后装饰 | 搜索、调用、回传、确认、审核、反馈、学习闭环优先于视觉复杂度 |

## 3. 公开互联网入口原则

Axiqra 面向互联网，公开首页和默认入口应优先回答：

1. Axiqra 是什么。
2. AI 工具和开发者为什么需要工程记忆。
3. 怎么搜索 Solution / Public Case / Candidate Seed。
4. 怎么让 AI 工具在任务前搜索、任务后回传。
5. Public Case 如何帮助人类学习真实工程路径。
6. 为什么内容可信：证据、验证等级、风险等级、审核、反馈。
7. 如何加入 early access、创建 Seed、接入 AI 工具。

团队、企业、小组、审计、SSO、私有化、内部权限等能力必须存在于产品体系中，但不应作为所有人的默认首页入口。

## 4. 登录态、空间和授权范围决定导航

未来原型的导航必须根据用户状态动态出现，但这里的“角色”不是互斥身份，也不是只能选择一个当前角色。

导航能力必须采用累加式权限渲染：

1. 用户登录后，先获得普通用户基础入口。
2. 用户加入团队、小组或企业后，在基础入口之外累加所属空间入口。
3. 用户获得企业管理员、审核者、Maintainer、认证开发者等高级身份后，只累加对应治理或管理入口。
4. 高级身份不得替换普通用户入口，也不得让用户失去所属组织成员入口。
5. 当前空间切换只改变写入指向、搜索倾向和默认上下文，不改变用户真实拥有的能力集合。
6. AI 工具 token 的 scope 只能裁剪工具通道能力，不能扩大用户在 Web 端不具备的权限。

实现上，导航应从 `base_user_nav + space_membership_nav + granted_scope_nav + governance_nav + admin_nav` 合并生成，并在合并后按权限、风险、对象状态和当前空间做二次裁剪。禁止用“当前角色 = 企业管理员 / 审核者 / Maintainer”直接替换整套导航。

| 能力来源 | 累加入口 | 显示条件 |
|---|---|---|
| 未登录状态 | 首页、Solution、Public Case、Trust、Early Access、登录 / 注册 | 不显示团队、企业、审核后台 |
| 登录基础身份 | 搜索、我的 Project Case、接入 AI 工具、Candidate Seed、反馈记录 | 所有登录用户保留 |
| AI 工具授权 | 接入状态、Search Before Act、Trace 回传、Feedback、doctor | 根据 token scope 和授权渠道裁剪 |
| 贡献者资格 | 我的贡献、Seed、Public Case 投稿、反馈、能力档案 | 有贡献记录或认证申请资格 |
| 团队成员关系 | 团队项目、团队 Case、团队 Solution、团队复用 | 只显示所在团队和项目 |
| 小组成员关系 | 小组项目、小组 Case、小组 Solution | 只显示所在小组 |
| 企业成员关系 | 企业项目、企业内部搜索、企业策略提示 | 只显示所在企业租户 |
| 企业管理员授权 | 成员、组织、小组、权限、审计、导出、授权撤回 | 在登录基础身份和企业成员入口之外累加 |
| 审核者授权 | 审核队列、风险分层、申诉处理、审核记录 | 在登录基础身份之外，按领域和授权范围累加 |
| Maintainer 授权 | 领域内容维护、Solution 合并 / 分叉 / 废弃、Seed 认领 | 在登录基础身份之外，只显示负责领域 |
| 官方审核授权 | 官方审核台、官方决策记录、治理审计 | 在登录基础身份之外累加，动作独立留痕 |

页面设计不得让未登录用户或普通用户误以为 Axiqra 是企业后台或权限管理系统。

### 4.1 未登录用户搜索和 MCP 搜索限额

未来页面必须显式支持“未登录用户搜索”场景，但只能作为公开互联网入口：

| 场景 | 入口 | 可搜索范围 | 禁止能力 | 页面表现 |
|---|---|---|---|---|
| 未登录用户 Web 搜索 | 首页、Solution Network、Public Case 搜索框 | Public Space 中已公开、已脱敏、允许展示的 Solution、Public Case、Candidate Seed 摘要 | 不得召回个人、团队、小组、企业、私有 Project Case；不得使用 MCP；不得导出；不得创建私有 Seed | 展示公开结果、可信等级、风险提示和登录 / 加入试点 CTA |
| 登录用户 Web 搜索 | 登录后搜索页、个人工作台、空间上下文搜索 | 普通用户基础入口 + 所属空间 + 授权范围累加后的可见内容 | 不得越过 ABAC、租户、空间和授权范围 | 保留普通用户入口，并按空间倾向排序 |
| 登录用户 MCP 搜索 | `axiqra.search_before_act` | token scope、用户登录态、空间成员关系和授权范围累加后的可见内容 | 普通登录用户 S1 默认每日最多 10 次 MCP 搜索；超额不得继续调用 | 超额时返回明确限额提示，引导等待次日或升级 / 申请更高额度 |

说明：MCP 搜索限额是工具通道能力限制，不应影响用户在 Web 端已经具备的基础导航入口。企业管理员、审核者、Maintainer 等高级身份只是在基础入口外叠加更多能力，不能绕过 MCP 搜索限额和 ABAC 裁剪。

## 5. 未来页面域

| 页面域 | 是否公开默认入口 | 说明 |
|---|---|---|
| 首页 / 传播页 | 是 | 开放互联网产品说明和 early access |
| Solution Network | 是 | 公共 Solution 搜索、可信展示、AI 调用说明 |
| Public Case | 是 | 人类学习真实工程路径 |
| Trust / 验证机制 | 是 | 验证等级、风险等级、审核和反馈机制 |
| Connect / AI 工具接入 | 是 | 对话式接入、MCP、CLI、API、doctor |
| Candidate Seed | 是 | 大众创建覆盖缺口，但要有质量门槛 |
| 个人工作台 | 登录后 | 我的项目、Project Case、Trace、Feedback |
| 贡献者中心 | 登录后 / 达标后 | 贡献账本、能力档案、认证入口 |
| 团队空间 | 加入团队后 | 团队内部工程记忆和复用 |
| 小组空间 | 加入小组后 | 小组内项目、Case、Solution 和权限 |
| 企业空间 | 企业成员后 | 企业内部搜索、权限、审计、导出 |
| 审核治理台 | 审核者后 | 风险分层审核、申诉、隔离、官方审核留痕 |

| 管理后台 | 管理员后 | 用户、空间、策略、数据治理，不面向普通入口 |

## 6. 页面设计顺序

未来原型不要一上来画所有后台页面。建议顺序：

1. 公开首页和传播页。
2. Solution 搜索与详情。
3. Public Case 学习页。
4. AI 工具接入页。
5. Search Before Act 结果页。
6. Engineering Trace Package 用户确认页。
7. 个人 Project Case 工作台。
8. Candidate Seed 创建与认领页。
9. 贡献者中心。
10. 审核治理台。
11. 团队 / 小组空间。
12. 企业空间和企业管理员后台。

团队和企业能力后画，不等于产品没有这些能力；它们是按登录态和权限出现的高级入口。

## 7. 公开页面风格基准

现有官网 `https://www.axiqra.com/` 的方向可以作为后续视觉参考：开放互联网产品、工程记忆层、Memory / Solutions / Trust / Early Access 的结构，比企业后台式入口更适合作为第一视觉。

建议保留的方向：

| 方向 | 原因 |
|---|---|
| Agent-ready engineering memory 的主叙事 | 能直接解释 Axiqra 的定位 |
| Search -> Apply -> Write back -> Evolve 的闭环表达 | 能让用户快速理解飞轮 |
| Personal / Team / Enterprise 作为受众说明 | 可以保留，但不应成为全局默认入口 |
| Trust 单独成段 | Axiqra 的可信机制是核心差异 |
| Public Case 示例 | 能让人看到不是普通知识库 |

建议调整的方向：

| 调整项 | 原因 |
|---|---|
| 团队和企业不要放成所有人默认工作入口 | 应根据登录用户身份动态显示 |
| 示例 Case 必须补技术版本和上下文 | 否则无法支撑 Solution 判断 |
| 公开页不展示复杂企业后台能力 | 避免互联网用户第一眼误判产品 |
| 早期 CTA 应聚焦加入试点、搜索、接入 AI 工具、创建 Seed | 更符合开放互联网增长 |

## 9. 原型启动条件

满足以下条件后再正式设计原型：

1. D01-D18 的主口径确认。
2. Excel 至少完成 S1 核心功能、页面、对象、API、权限、验收和测试拆解。
3. 12 大类和二级路线确认。
4. 公开入口、登录后入口、团队 / 小组 / 企业入口的累加式显示规则确认。
5. 核心对象字段和状态机确认。
6. 搜索、回传、审核、反馈、授权撤回闭环确认。
