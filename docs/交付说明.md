# Axiqra 文档交付说明

## 1. 本次交付目标

本次交付的目标不是压缩 Axiqra 的产品范围，而是把“大而全”的产品愿景整理成一套可以继续拆功能点、排开发、做验收的文档体系。

Axiqra 当前被定义为：AI Agent 时代的工程解决方案记忆层。它既服务 AI 工具调用，也服务人类开发者学习；既沉淀私有项目经验，也能在授权、脱敏、审核和验证后进入公共知识飞轮。

本次交付重点覆盖以下内容：

- 产品介绍与全流程总览。
- 产品闭环图谱与关键子闭环。
- 用户、AI Agent、人类学习、团队企业、社区贡献、认证身份等主流程。
- Engineering Trace Package、Case、Public Case、Project Case、Solution、Candidate Seed、Review、Feedback 等核心对象。
- AI 工具接入、Search Before Act、执行回传、Prompt / Rule / Skill 记忆边界。
- 搜索、推荐、排序、验证等级、权限空间、内容治理、贡献激励、社区治理、冷启动和商业验证。
- 开发任务拆解、验收标准、风险登记、文档维护机制。
- Excel 功能开发与验收明细表。

## 4. 当前文档状态判断

当前文档已经从“愿景讨论”进入“可验收、可拆任务、可排开发”的阶段。第二轮补充后，D05-D18 已经从“体系骨架版”提升为“v0.2 开发规格增强版”。

真实说明：这仍不是最终 4000 到 8000 个末级功能点的完整明细版。当前已经完成一级、二级和关键三级能力的结构化整理，并补齐了继续扩展到末级任务所需的对象字段、状态迁移、API / MCP / CLI、权限策略、审核规则、搜索排序、贡献治理、冷启动和开发 Gate。

本轮新增的深度包括：

| 文档范围 | 补强内容 |
|---|---|
| D05 | 流程节点到对象、接口、权限、状态、审核和测试的开发规格映射 |
| D06-D07 | 字段矩阵、Engineering Trace Package 结构、Project Case / Public Case 内容字段、脱敏清单、Case 到 Solution 提取规则 |

后续如果按日本式开发继续推进，建议不要直接追求一次性写完 8000 行，而是按以下方式扩展：

1. 先锁定 12 个大类和 D01-D18 文档边界。
2. 每个大类拆 8 到 20 条二级路线。
3. 每条二级路线拆功能点、页面点、对象字段、API、验收条件、测试用例。
4. 每个功能点必须能对应到文档编号、页面编号、对象编号、验收编号和风险编号。
5. 先把 S1 MVP 拆到可开发颗粒度，再把 S2-S4 做预留，不混在同一个冲刺里。
