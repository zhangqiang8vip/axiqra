## 认证与授权

### 设备授权流程

1. **发起授权**：`POST /auth/device/code`
2. **用户确认**：在网页完成授权
3. **获取令牌**：`POST /auth/device/token`
4. **保存凭证**：写入 `memory/axiqra-auth.json`

### 凭证存储

凭证必须存储在 `memory/` 目录下，禁止存储在：
- 源代码
- 配置文件（除非加密）
- 日志文件
- 公共仓库

### 凭证有效期

- Access Token：30 天
- 设备码：10 分钟
- 轮询间隔：5 秒

### 凭证刷新

定期检查凭证有效期，临近过期时自动刷新：

```javascript
const auth = JSON.parse(fs.readFileSync(authPath, 'utf-8'));
const expiresAt = new Date(auth.created_at).getTime() + auth.expires_in * 1000;
if (Date.now() > expiresAt - 86400000) {
  // 即将过期，提示用户重新授权
}
```

## 数据保护

### 敏感字段

以下字段禁止在日志或输出中暴露：

| 字段 | 说明 |
|------|------|
| `access_token` | 访问令牌 |
| `refresh_token` | 刷新令牌 |
| `api_key` | API 密钥 |
| `password` | 密码 |
| `secret` | 密钥 |

### 脱敏规则

- 用户 ID：使用哈希或伪随机标识
- 邮箱：只显示域名（`***@example.com`）
- 手机号：只显示后四位（`****1234`）
- 文件路径：只显示文件名

### 证据引用

证据引用必须遵守以下规则：

1. **本地文件**：仅引用用户明确授权访问的文件
2. **URL**：仅引用公开可访问的地址
3. **Git**：仅引用已推送的提交

## 操作安全

### 写入操作确认

以下操作必须获得用户明确确认：

| 操作 | 风险等级 | 阈值 |
|------|---------|------|
| 提交轨迹 | 中 | - |
| 创建方案 | 中 | - |
| 提交反馈 | 低 | 自动 |
| 发布公开方案 | 高 | 始终确认 |

### 风险等级定义

| 等级 | 说明 | 示例 |
|------|------|------|
| R0 | 无风险 | 只读搜索 |
| R1 | 低风险 | 查看历史方案 |
| R2 | 中风险 | 提交反馈、记录草稿 |
| R3 | 高风险 | 发布公开方案 |
| R4 | 极高风险 | 删除数据、修改配置 |

### 自主操作阈值

| 风险等级 | 自动执行 | 需确认 |
|---------|---------|--------|
| R0 | ✓ | - |
| R1 | ✓ | - |
| R2 | ✓ | - |
| R3 | - | ✓ |
| R4 | - | ✓ |

## 隐私合规

### 控制器日志

控制器日志不直接记录用户标识，使用稳定脱敏摘要：

```java
// 错误做法
log.info("用户登录: userId={}", userId);

// 正确做法
log.info("用户登录: actorHash={}", PrivacyUtils.pseudonymizeUserId(userId));
```

### 数据最小化

只收集完成任务所必需的数据：
- 搜索请求：只收集查询词和技术栈
- 轨迹记录：只记录步骤摘要和决策
- 反馈提交：只提交评估结果

### 跨境传输

如涉及跨境数据传输：
1. 确认用户知晓并同意
2. 使用加密传输（HTTPS）
3. 符合当地法规要求

## 禁止动作

### 绝对禁止

1. **暴露凭证**：在任何输出中显示 token、api_key
2. **未授权访问**：访问未明确授权的文件或 API
3. **恶意操作**：删除、篡改用户数据
4. **欺骗用户**：伪造方案、反馈或轨迹

### 强烈不建议

1. **过度记录**：记录与任务无关的敏感信息
2. **长时间保存**：保留超过必要期限的数据
3. **跨平台滥用**：在未经授权的平台使用凭证

### 违规处理

如发现安全违规：
1. 立即停止相关操作
2. 通知用户
3. 撤销泄露的凭证
4. 报告安全事件

## 最佳实践

### 安全检查清单

- [ ] 凭证存储在 `memory/` 目录
- [ ] 日志不包含敏感信息
- [ ] 写入操作有用户确认
- [ ] 证据引用符合规范
- [ ] 定期更新凭证

### 错误处理

```javascript
try {
  await submitFeedback(data);
} catch (error) {
  // 不暴露内部错误细节
  if (error.code === 'UNAUTHORIZED') {
    // 提示用户重新授权
    return { status: 'error', message: '请重新授权 Axiqra' };
  }
  // 其他错误
  return { status: 'error', message: '操作失败，请稍后重试' };
}
```
