## MCP 层 - 工具调用

### 7 个工具

| 工具 | 用途 | 调用时机 |
|------|------|----------|
| `search_before_act` | 任务前搜索 | 每次任务开始 |
| `submit_trace` | 提交轨迹 | 任务完成后 |
| `submit_feedback` | 提交反馈 | 任务完成后 |
| `get_solution` | 获取方案详情 | 需要时 |
| `get_public_case` | 获取公开案例 | 需要时 |
| `create_seed` | 创建种子方案 | 无历史时 |
| `doctor` | 接入诊断 | 配置检查 |

## Rule 层 - 行为规范

### Axiqra Agent Rules

```
1. 任务前: 调用 search_before_act 搜索历史方案
2. 无历史: 作为开发者创建方案 + 调用 create_seed 贡献
3. 任务后: 调用 submit_trace 记录分析过程
4. 完成后: 调用 submit_feedback 评价结果
5. 诊断:   调用 doctor 检查接入状态
```

### Cursor Rules 配置

```markdown
# axiqra-agent-rules.md

## 任务前规则
- 总是先调用 `axiqra.search_before_act` 搜索历史方案
- 如果返回空结果，作为开发者创建新方案

## 开发贡献规则
- 无历史经验时，调用 `axiqra.create_seed` 沉淀新经验
- 描述: 任务目标、覆盖缺口、证据提示

## 轨迹记录规则
- 任务完成后，调用 `axiqra.submit_trace`
- 记录: task_goal, forward_path, decision_path, outcome

## 反馈评价规则
- 调用 `axiqra.submit_feedback`
- 评价: worked/partial/failed/not_applicable
```

## Skill 层 - 能力定义

### Axiqra Agent Skills

```
┌─────────────────────────────────────────────────────────────┐
│ Axiqra Agent Skill                                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│ ## 能力描述                                                 │
│ 本 Agent 具备 Axiqra 智能助手能力，通过 MCP 协议与          │
│ Axiqra 平台交互，实现知识复用和经验沉淀。                    │
│                                                             │
│ ## 核心技能                                                 │
│                                                             │
│ ### 1. 历史方案搜索 (search_before_act)                     │
│ - 任务前自动搜索相似历史方案                                │
│ - 返回 fit_score, verification_level, risk_level           │
│ - 高置信度方案可直接复用                                    │
│                                                             │
│ ### 2. 轨迹记录 (submit_trace)                              │
│ - 记录分析过程: forward_path (执行路径)                     │
│ - 记录决策过程: decision_path (决策路径)                    │
│ - 记录结果: outcome (success/failure/partial)                │
│                                                             │
│ ### 3. 反馈评价 (submit_feedback)                            │
│ - 评价方案有效性: worked/partial/failed                     │
│ - 积累反馈数据用于方案优化                                  │
│                                                             │
│ ### 4. 种子创建 (create_seed)                                 │
│ - 无历史方案时，创建新的种子方案                            │
│ - 沉淀新经验供后续复用                                      │
│                                                             │
│ ### 5. 接入诊断 (doctor)                                     │
│ - 检查: network, auth, quota, version, config, storage      │
│ - 确保 MCP 接入正常                                          │
│                                                             │
│ ## 双重角色                                                 │
│                                                             │
│ | 角色 | 场景 | 行为 |                                      │
│ |------|------|------|                                      │
│ | 复用者 | 有历史方案 | 搜索 → 复用 → 记录 |                  │
│ | 开发者 | 无历史方案 | 搜索 → 空 → 自行开发 |               │
│ | 贡献者 | 无历史方案 | 创建 Seed 沉淀经验 |                 │
│ | 执行者 | 任务完成 | 提交轨迹记录 |                         │
│ | 反馈者 | 任务完成 | 提交使用反馈 |                         │
│                                                             │
│ ## 使用场景                                                 │
│                                                             │
│ 1. 后端问题排查                                             │
│    → 搜索历史方案 → 分析问题 → 记录轨迹                      │
│                                                             │
│ 2. 新技术探索                                               │
│    → 搜索 → 无结果 → 开发方案 → 创建 Seed → 记录轨迹        │
│                                                             │
│ 3. 方案有效性验证                                           │
│    → 应用方案 → 提交反馈 → 积累数据                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
